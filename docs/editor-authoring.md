# Editor authoring milestone

Baseline: feature/example-games, 45cac43. MeadowRun and Skybound run on the user's Windows AMD machine. No new hardware verification is implied.

## Audit and implementation order

Source is authoritative. Scene owns registry, UUID map and authored fields. Entity is a borrowed observation; Copy keeps UUIDs for Play but clears physics/native owners. Duplicate creates a new UUID. SceneSerializer stages all resources before commit and uses atomic writes. Managed handles belong to the active Mono domain; authored metadata contains no domain pointers. RuntimeSession owns transitions and cancels them at Stop. Dynamic physics is synchronized between callbacks and physics steps, but managed iteration was over the live registry and managed cleanup had no OnDestroy callback.

Projects stage scene/assembly/browser before replacing the session. Paths resolve against explicit project asset roots; legacy absolute resources are readable but cannot be exported. There is no asset database or hierarchy. Existing prefab-like content is fixed named entities. Skybound's fit camera expands the visible height while its ground remains at an authored Y and nine-unit pipes extend below it. MeadowRun has one expedition scene. Existing ImGui settings are in platform user data, seeded once from resources; preserve this migration and existing layout. Script inspector exposes only floats and a free-form class name. Project New is an in-memory object, not a creation workflow. The canonical Premake Python command already owns managed compilation, build locks, atomic assembly deployment, dependency closure and transactional packages. Tests include real Application/ImGui and platform desktop input, plus Linux/Windows Debug/Release and extracted archives in CI.

Order: shared process/toolchain discovery and authoring services; preferences/project configuration and responsive jobs; bounded single-entity prefab and callback-safe lifecycle; editor workflows; example migration/presentation/levels; service/UI/platform/package verification; review and push.

## Navigation and scopes

File: New/Open/Recent projects, Save project, scene operations. Project: Settings, Create Script, Build Scripts, Export Game, Open Folder, Reload Scripts. Edit: Preferences. Content Browser: assets and prefab inspection. Entity inspector: class chooser, authored fields, Create Prefab. Prefab inspector: detached entity properties, dirty/save, transform and Instantiate. Output: shared diagnostics and operation status.

Preferences follow the user: external editor, SDK, Python, UI scale, collider visibility and recents, versioned under platform user data/Hazel/Hazelnut. Project descriptor: portable display name, startup scene, assets and assembly. Existing descriptors default to version 1. Layout remains in the existing imgui.ini; no new workspace taxonomy. Writes occur on explicit Save/Apply, not every frame. Capabilities are read-only. No machine paths in descriptors.

## Bounded scope

Single-entity detached prefabs reuse scene serialization, reject native scripts and external entity references; self references remap to each instance. No hierarchy, nested prefabs, inheritance, variants or propagation: these require an asset identity/dependency system and are deferred. A typed prefab field is a managed value with a serialized project-relative reference, never an opaque unvalidated string presented as an asset. Managed gameplay remains C#. The editor generates a concise sample and opens sources in the configured application.

Native compilation/export targets the host only, using a configured source SDK. Packaged editing/Play needs no SDK/Python; builds and exports do. No implicit checkout search, installation or cross-compilation. Cancellation is deferred for compiler/export jobs because terminating arbitrary build children can leave compiler state; shutdown joins jobs and the UI explicitly states this. Discovery probes time out after five seconds. Every export performs canonical incremental Release builds of engine/runtime and project scripts before packaging.

## Python contract

Priority: explicit Preferences path (invalid means error); intentional SDK tooling interpreter; OS candidates in stable order; PATH supplement. Linux: /usr/bin/python3, /usr/local/bin/python3, supported /opt/python version installations then PATH. Windows: registered PythonCore HKCU then HKLM (64 then 32 bit views, version keys descending), known installer directories descending version, then PATH; WindowsApps aliases rejected. Probe is isolated, bounded to five seconds, requires Python >=3.9 and standard subprocess/pathlib/json functionality, returns real executable and version. Every operation revalidates; diagnostics show source/path/version. Invocation is absolute with separate arguments and explicit cwd. SDK/tool prerequisites are separate diagnostics. No environment mutations unless canonical toolchain requires them.

## Delivered authoring operations

- **File > New Project**: display name, technical identifier, new destination folder, Browse parent, file summary, readiness, Create and Open. A failed build leaves the current project/session and destination unchanged. Destination must not exist. Starter includes camera/text, source example, canonical Premake, and Debug assembly. The shared CLI is `hazel.py new-project --name ... --identifier ... --destination ...`.
- **File > Open Project / Recent Projects**: staged project replacement; missing recent entries are disabled and can be removed. Scene operations and Exit offer Save/Discard/Cancel when authored content would be discarded. Window close uses the same guard. Tool jobs exclude project replacement.
- **Project > Project Settings**: portable display name, read-only technical build identifier, assets folder, startup scene chooser and compiled assembly chooser. Validate/stage the scene, save atomically and reopen through the existing project loader; failed application restores the descriptor/session. Stop Play before applying.
- **Properties > Create Prefab** (also entity context menu): choose a new project asset path or browse its folder. **Content Browser** labels prefabs; click one for **Prefab Inspector**, edit standard components/fields, Save, set initial transform, Instantiate and Select. Drag a prefab onto Viewport for an instance. Instances are detached; prefab saves affect future instances only. Invalid/unsupported data is rejected before mutation.
- **Project > Create Script**: class and namespace validation, minimal C# lifecycle/Instantiate/Destroy sample, Create and Open. Select a `.cs` in Content Browser or **Properties > Open Script** to edit. **Properties > Script > Class** lists compiled classes; numeric, bool, vector, entity and typed prefab fields have authored controls. Use C# default clears an override. Unset controls do not claim to show constructor defaults. Unsupported managed types are not advertised.
- **Project > Build Scripts**: preflight, Debug build, streamed diagnostics, automatic assembly reflection/reload when done. Compilation and canonical atomic deployment retain valid assemblies on failure. Stop Play first. CLI uses the same `script-build` service.
- **Project > Export Game**: active project, host platform x64, Release, destination browse, package name, readiness and Export. Orchestrates incremental Release engine/runtime and project scripts, validates resources/assemblies/native closure, publishes the completed archive transactionally. Open Output Folder shows resulting archives/checksums. CLI shares `editor-export`, which calls the existing build/script-build/package implementations under one lock. No second packaging implementation.
- **Edit > Editor Preferences**: machine Python executable with Browse, Auto-detect and Validate; source/configured status, actual path/version/errors; SDK folder; external editor; UI scale and collider overlay; Apply and Save and Reset. Detected renderer vendor/device/limits are read-only. Packaged editing/Play remains available without development tools.
- **Window > Output**: dockable progress and stdout/stderr with completion/error status. Workers contain immutable argv/path snapshots, own their process tree, never call ImGui or access scenes. Completion is applied only to its project. Only one tool job per editor; SDK CLI locks exclude other processes. Native jobs are not user-cancellable; the interface says shutdown waits for them. Probe timeout is five seconds; tool timeout sixty minutes.

## Runtime contracts

`Hazel.Prefab` is a typed managed asset reference, authored through a prefab chooser. `Entity.Instantiate(prefab, position[, rotation, scale])` validates and loads a one-entity asset before adding it with a fresh UUID. Returned handle is scene-owned and valid immediately; `As<T>()` is available after startup. Position-only placement preserves authored rotation/scale; the full overload replaces them. Initial transform and copied authored values precede physics and exactly-once OnCreate. Callback iterations snapshot UUIDs; created entities start at the safe boundary and receive their first update in a later snapshot. `Destroy()` invalidates immediately, repeated calls are harmless, and OnDestroy/handle/physics cleanup happens outside iteration. A scene identity token prevents stale wrappers from binding a reused authored UUID after transitions. Retired scene/session operations are cancelled at Stop; cleanup and domain replacement reject new instantiation. Assembly replacement cleans up old instances, then restores compatible field snapshots into new instances. Managed threads cannot borrow the main-thread scene. `Scale` supports rendered entities; physics scale must be supplied before startup in the prefab's initial transform.

A prefab cannot serialize native factories, body/fixture pointers, Mono handles or outside entity references. Null references stay null; self references remap. Texture and prefab resources must be inside project Assets, including symlink destinations. No instance link is serialized.

## Example design

Skybound retains its parallax cloud scripts and fixed-step fair scoring/restart model. Gameplay gate slots describe bounded simulation state; each new spawn generation destroys the former pipe pair and instantiates new UUIDs from UpperPipe/LowerPipe assets. Lower geometry terminates exactly at the -4 collision floor. Camera-derived floor fill extends continuously from the ground artwork to below the visible window bottom at any aspect ratio; no pipe geometry continues beneath it.

MeadowRun now proceeds Camp Meadow → Orchard Paths → Lantern Grove → Trail Restored. Each stage has five lantern seeds, a pond checkpoint preserving collected progress, a north-east exit, current-level restart, and title-menu navigation. Orchard rows and open grove/rock islands change traversal and objective spacing. Seeds use a typed prefab field and are destroyed on pickup. Pond and Tree assets support reuse through detached editor instantiation. No new artwork or license dependencies are introduced.

Build identifier/workspace renaming is deferred: it requires updating custom Premake definitions safely. The identifier is configured in New Project and shown read-only in Project Settings. Changing the display name is supported independently.
